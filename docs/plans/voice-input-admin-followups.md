# 音声入力の管理画面の積み残し（破棄理由の可視化 / プリセット / 送信猶予）

2026-08-05 作成。実装プラン。`docs/plans/always-on-voice-input.md` の後始末。

## 目的・背景

常時入力（Phase 3〜6）を入れた結果、**発話が無反応で消える理由が 5 通り**になった。

```
レベル棄却 / prompt エコー / AI 発話のエコー / 相槌 / 語数不足
```

どれも仕様どおりの動作だが、**理由が会話ログにしか出ない**。しきい値を追い込む場所は
管理画面「音声入力」なのに、そこに判断材料が無いのが噛み合っていない。
あわせて、監査で見つかった設定まわりの積み残しを片付ける。

## 対応方針

### Step 1: 破棄理由をセグメントの実測へ載せる

- `SpeechSegmentMeasurement` に 2 つ足す。**どちらも Optional にする**（既存の保存データが
  デコードできなくなると、直近 20 件が黙って消えるため。合成 Codable は非 Optional の
  新フィールドを既存 JSON から読めない）
  - `discardReason: SegmentDiscardReason?` — レベルゲート以外の破棄理由
    （`promptEcho` / `assistantEcho`）
  - `startedDuringPlayback: Bool?` — 読み上げ中に始まったセグメントか
    （＝ 厳しいしきい値とエコー判定が掛かった対象）
- `.segmentMeasured` の yield は**破棄の判定が済んでから**に移す（今は判定前に出している）
- 会話ログの 1 行（`logLine`）と管理画面の一覧の両方に反映する
- **相槌・語数の破棄はここに出せない**。ターン全文に対する判定でセグメント単位ではないため。
  必要になったら「直近の破棄ターン」を別枠で持つ（今回はやらない）

### Step 2: プリセットに「AI のターン中」の 2 項目を持たせる

- いまプリセットは 7/9 項目しか持たず、適用すると AI ターン中の 2 項目が既定へ戻る
  （画面のフッターで断っているだけ）。プリセット側に値を持たせて意図を明示する
- 部屋が騒がしいほど読み上げ音量も上がる ＝ エコーも増える、という関係で出し分ける

### Step 3: 送信猶予を画面に出す

- `TurnCommitGrace.standard` は全ターンのレイテンシに効くのに、コード既定（1.0 秒）固定で
  画面から触れない（`docs/plans/always-on-voice-input.md` の Phase 6 の積み残し）
- **画面に出すのは標準値だけ**。長短（続きそう / 完結）は標準からの固定比で導く既存の設計を保つ
- 0 にすると従来どおりの即送信へ戻せる
- 最小語数と同じセクション（**ターンの締め方**）にまとめる。どちらも「ターンをいつ・
  送るかどうか」の話で、VAD のしきい値とは層が違う

## 影響範囲

| ファイル | 変更 |
| --- | --- |
| `Voice/SpeechLevelGate.swift` | `SpeechSegmentMeasurement` に破棄理由・読み上げ中フラグ、`SegmentDiscardReason` 新規 |
| `Voice/TurnBasedVoiceSession.swift` | `.segmentMeasured` の組み立てを判定後へ移す、`commitGrace` を設定から受ける |
| `Settings/VoiceInputSettingsStore.swift` | 送信猶予の保存、プリセットの 2 項目 |
| `Admin/VoiceInputSettingsView.swift` | 「ターンの締め方」セクション、実測一覧に破棄理由 |
| `Conversation/ChatRoomStore.swift` | `configuration.commitGrace` を流し込む |

- 保存データの互換: 追加は Optional なので既存の直近セグメントはそのまま読める
- 音声パスの挙動は変えない（Step 1・2 は表示と既定値、Step 3 は既定 = 現行値のまま）

## 実装メモ（2026-08-05）

3 Step とも入れた。**音声パスの挙動は変えていない**（表示・保存・既定値だけ）。

- **Step 1**: `SegmentDiscardReason`（`promptEcho` / `assistantEcho`）と
  `startedDuringPlayback` を `SpeechSegmentMeasurement` へ。どちらも Optional なので
  保存済みの直近 20 件はそのまま読める（テストで旧 JSON のデコードを固定した）
  - `.segmentMeasured` の組み立てを**破棄の判定より後ろ**へ移した（今までは判定前に出しており、
    採否がレベルゲートの結果しか反映していなかった）
  - `isAccepted` / `outcomeReason` を生やして、会話ログの 1 行と管理画面の一覧が同じ理由を出す
  - エコー破棄の `.info` は**やめた**（一覧に出るようになったので会話ログの二重掲載になる）
- **Step 2**: プリセットが 9 項目すべてを持つようにした。屋外だけ ×2.0 / 0.35 秒
  （騒がしい場所ほど読み上げ音量も上がる ＝ エコーも増える）。
  「欠けている項目が無いこと」をテストで固定したので、今後 `VoiceInputParameter` を足したら
  プリセット側の追従漏れがテストで落ちる
- **Step 3**: 送信猶予（標準値）を「ターンの締め方」セクションへ。最小語数と同居させた
  （どちらも認識の後で効く層で、VAD のしきい値とは別）。0 秒で即送信＝ 2026-08 以前の挙動へ戻る
  - `commitGraceSettings()` が `TurnCommitGrace` を組み立てる。**長短の比は既定のまま**で
    標準値だけ差し替える（画面に出すのは 1 つだけ、という Phase 1 の設計を保つ）
- 全 495 件 green・シミュレータビルド確認済み

## テスト方針

- **ユニット**
  - `SpeechSegmentMeasurement`: 旧 JSON（新フィールド無し）がデコードできること、
    `logLine` に理由が出ること
  - `VoiceInputSettingsStore`: 送信猶予の保存・丸め・既定と同じなら保存しない・
    「すべて既定に戻す」で戻ること / プリセットが 9 項目すべてを入れること
- **シミュレータ**: 全テスト + 管理画面の表示
- **実機**: 相槌・エコーで消えたときに管理画面「音声入力」の一覧で理由が読めること、
  送信猶予を 0.4 秒に下げると応答が速くなること
