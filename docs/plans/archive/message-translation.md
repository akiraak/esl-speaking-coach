# 会話の翻訳生成とタップでの表示切替

## 目的・背景

トーク画面の会話はすべて英語で、意味が取れないまま流れていくことがある。会話の邪魔をせずに意味を確認できるよう、
各発話（AI・自分の両方）に日本語訳を持たせ、**吹き出しをタップすると訳の表示 / 非表示が切り替わる**ようにする。

- 会話中の視界を汚さないため、訳は**既定で非表示**。タップしたメッセージだけ開く
- 会話の流れを止めないため、翻訳生成は**会話ターンのクリティカルパスに載せない**（別 API・非同期）
- 訳は端末内に永続化し、起動後にタイムラインを遡ってもタップ 1 回で読める

## 方針

### 生成タイミング: ターン終了ごとに先行生成（＋履歴は遅延生成）

| 方式 | 採否 | 理由 |
| --- | --- | --- |
| ターン終了後にまとめて先行生成 | **採用** | 会話に追従して訳が埋まる。1 ターン = 1 リクエストなので呼び出し回数も少ない |
| 表示を ON にした時点で未翻訳分を一括生成 | 併用 | 起動時に復元した過去セッション（`translation` が nil）をカバーする |
| 会話ターンの応答に訳も含める | 不採用 | system prompt / 出力形式が変わり TTS の文分割とキャッシュに影響。レイテンシも増える |

先行生成のトリガは `VoiceSessionEvent.stateChanged(.listening)`（= AI のターンが終わって聞き取りに戻った時点）。
その時点で未翻訳の発話（直前の user 発話 + AI 発話群）をまとめて 1 リクエストで翻訳する。セッション終了時にも
フラッシュする。失敗は best effort（次のフラッシュか、後述の一括生成でカバー）。

**先行生成は訳の表示が ON のときだけ行う。** 訳を使わない日に無駄な API 呼び出しをしないため。
OFF → ON にした時点で、タイムライン上の未翻訳分をまとめて生成する（下記「表示」参照）。

### 翻訳モデル: `claude-haiku-4-5`

短文の英日翻訳に sonnet は過剰。単価は $1 / $5 per 1M（sonnet-5 の 1/2〜1/3）で、1 ターン数十トークンなので
セッションあたりのコストは無視できる水準。

- 非ストリーミング / structured outputs（`output_config.format` の json_schema）で `[{id, ja}]` を受け取る
- **`output_config.effort` は haiku-4-5 では 400 になるため送らない**（`temperature` / `top_p` / `top_k` も従来どおり送らない）
- system prompt は固定文（プロンプトキャッシュの最小プレフィックスには届かないので `cache_control` は付けない）
- 話者名（Chobi / Naruko / Learner）を添えて渡し、口語の英語を自然な日本語にする

### 文脈（トピック・直前の会話）を必ず渡す

英会話は代名詞と省略が多く（`Yeah, I did.` / `That one.` / `It was.`）、1 発話だけを見て訳すと意味が痩せる。
リクエストは常に次の 2 部構成にする。

1. **文脈**（訳さない・参照専用）: トピック名 + 対象発話の直前 8 発話（話者ラベル付き。足りなければあるだけ）
2. **翻訳対象**（`id` 付き）: 今回訳す発話

system prompt に「文脈は訳出せず、対象の発話だけを、文脈に照らして自然な日本語にする」ことを明記する。
出力は対象発話の `id` 分だけ。

- **先行生成**（ターン終了時）: タイムラインの現在セッション区間から直前 8 発話を取る
- **一括生成**（表示を ON にしたとき）: チャンクの先頭発話より前の 8 発話を、同じセッション内から取る
  （セッション区切りをまたいで文脈にはしない）
- キャッシュは元々効かせていないので、文脈が毎回変わることによる不利益はない。追加トークンは haiku で数百程度

### 翻訳対象

AI 発話とユーザー発話の**両方**。ユーザー発話の訳は「STT が何を拾ったか」の確認にもなる。
トピックカード・フィードバックカード・システム通知は対象外（元から日本語）。

### 表示: タイムライン下端のトグルボタンで一括切替

吹き出しタップは操作が見つけにくいため採らない。**セッション終了ボタンと同じ下端の固定行にトグルボタンを並べ、
タイムライン全体の訳表示を一括で ON / OFF する**。

```
┌──────────────────────────────────────────┐
│  [ 🇯🇵 訳 ]  [ 🏁 このトピックを終了     ] │  ← セッション中
└──────────────────────────────────────────┘
┌──────────────────────────────────────────┐
│  [ 🇯🇵 訳 ]                                │  ← セッション外（履歴閲覧中）
└──────────────────────────────────────────┘
```

- 訳ボタンは**セッション中かどうかに関わらず常時表示**（過去ログを遡って読むときにも使うため）。
  終了ボタンは従来どおりセッション中のみ表示し、その場合は横並びにする
- ON / OFF は `UserDefaults` に保存し、アプリ再起動をまたいで保持する（`inputMode` と同じ扱い）
- ON のとき、各吹き出しの下に訳を小さめの文字で表示する。未生成の発話は「翻訳中…」、失敗は「翻訳できませんでした」
- 切替は `withAnimation`。ON にした直後は自動スクロール中なら最下部へ追従させる（`timelineRevision` を増やす）

### 翻訳の対象範囲: 1 セッション分だけ

タイムラインには直近 10 セッションが復元されるが、**訳を生成するのは常に 1 セッション分だけ**にする。
遡って読み返したいのは直前のトピックまでで、それより前まで訳すのは費用も待ち時間も無駄になるため。

| 状態 | 生成対象 |
| --- | --- |
| セッション中 | **現在のセッション**（最後のセッション区切り以降）のみ |
| セッション外（終了直後・起動直後） | **直前の 1 セッション**（タイムライン末尾のセッション区切り以降）のみ |

- **表示は生成対象より広い**: 保存済みの訳があればどのセッションの吹き出しでも表示する。
  そうしないと新しいトピックを始めた瞬間に前のセッションの訳が画面から消えてしまう
- 生成対象外のセッションの未翻訳発話には「翻訳中…」も出さない（訳行そのものを出さない）

**ON にしたときの一括生成**: 上記の対象セッションのうち未翻訳の発話をまとめて生成する。
最大 20 発話ずつのチャンクで順次リクエストする（並列にはしない）。生成済みの分から順に表示が埋まる。
OFF のときは生成しない。

## テスト方針

- ユニット
  - `TranslationClient`: リクエストボディに `effort` / `temperature` が含まれないこと、model が `claude-haiku-4-5`、
    structured outputs スキーマの形、`stop_reason: "refusal"` で `content[0]` を読まずに throw すること、
    id と訳の対応がパースできること、usage の kind が `.translation` であること、
    **文脈（トピック + 直前 8 発話）が本文に含まれ、かつ文脈側の発話には `id` が振られていないこと**
    （＝訳出対象として返ってこない形になっていること）
  - 文脈の切り出し: 直前 8 件・8 件未満・セッション先頭（文脈なし）の各ケース
  - `ChatHistoryStore`: 翻訳の保存 → 再取得、未翻訳のとき nil、セッション削除で cascade
  - `AIPricing`: haiku の推定額
  - `ChatRoomStore`: 生成対象セッションの切り出し（セッション中 / セッション外 / セッションが 1 つも無い）、
    その中の未翻訳メッセージの抽出、20 件チャンクへの分割、`isTranslationVisible` の UserDefaults 往復
- 手動（シミュレータ）: 訳 OFF で 1 ターン会話 → 翻訳リクエストが飛ばないこと、ON にすると対象セッション分だけが
  順に埋まり、それより古いセッションには訳行が出ないこと、新しいトピックを始めても前セッションの訳が消えないこと、
  ON のまま会話 → ターンごとに訳が付くこと、OFF で訳が消えること、アプリ再起動で ON / OFF が復元されること、
  セッション中は 2 ボタン・セッション外は訳ボタンのみで最新メッセージがボタンに隠れないこと、機内モードでのエラー表示
- 実機: 会話中のレイテンシに影響が出ていないこと（翻訳は非同期なので理論上は影響なし）

## 未確定・判断が必要な点

- 訳の表示はタイムライン全体の一括 ON / OFF のみ。発話単位の個別開閉は持たない（操作が分かりにくいため）
- 生成は 1 セッション分のみ。それより古いセッションを後から訳す導線（「このトピックも訳す」ボタン等）は今回作らない。
  必要になったら追加する
