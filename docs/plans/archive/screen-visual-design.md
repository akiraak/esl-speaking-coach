# 画面ビジュアルデザインの選定

## 目的・背景

画面レイアウト・仕様は確定済み（`docs/specs/screen-layout.md`）。次に、トーク画面の**見た目（配色・吹き出しスタイル・トーン）**を決める。デザイン案を複数作成し、ユーザーが選ぶ。

## 対応方針

1. トーク画面のデザイン案を 4 案、HTML モックアップ（アーティファクト）として作成する
   - 各案は仕様書のレイアウト要素（ヘッダ / セッション区切り / AI・ユーザー吹き出し / トピックカード / 入力バー音声・テキストモード）を同一構成で含め、見た目だけを変える
2. ユーザーが選んだ案（または組み合わせ・調整指示）を `docs/specs/screen-layout.md` に「ビジュアルデザイン」節として追記する

## デザイン案

- 案 A: LINE ライク（淡ブルーグレー背景 + 白吹き出し + 緑のユーザー吹き出し）
- 案 B: iOS ミニマル(iMessage 風。システム背景 + グレー/ブルー吹き出し)
- 案 C: ダークモダン（ダーク背景 + ティール系アクセント）
- 案 D: ポップ・フレンドリー（暖色背景 + カラフルなキャラ配色。学習アプリ風）

## 影響範囲

- ドキュメント（`docs/specs/screen-layout.md` への追記）とモックアップのみ。コード変更なし
- 決定したデザインは「会話画面の UI」実装の前提になる

## テスト方針

- 仕様策定のみのためビルド・テストは不要
