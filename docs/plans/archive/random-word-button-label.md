# 「ランダムに選ぶ」を未練習からのランダムだと分かる表示に変える

## 目的・背景

単語カードの「ランダムに選ぶ」は**未練習の語**からランダムに出題するが、
ボタンの文言からは母集団が分からない（単語帳全体からのランダムに見える）。
前タスク（docs/plans/archive/word-card-counts.md）でカードに
`練習済み 4/14語 28%・未練習 10語` の集計が出るようになったので、
ボタンも「未練習から」と明示すると集計行と繋がって挙動が読める。

## 決定サマリ

| 項目 | 決定 | 理由 |
| --- | --- | --- |
| 通常時の文言 | **「未練習からランダムに選ぶ」** | 前プランの文言案どおり。直上の集計行の「未練習 N語」と語が揃う。このボタンは 1 つで 1 行を使うので横幅も足りる |
| 全語練習済み（集計で未練習 0語）のとき | **「全語からランダムに選ぶ」** | 実挙動は全語フォールバック（`randomWordChoice`）。直上に「未練習 0語」と出ているのに「未練習から」を出すと嘘の表示になる。文言をフォールバックの事実に合わせる |
| 集計が取れていないとき（tally nil） | 従来どおり **「ランダムに選ぶ」** | シークレット未設定・取得失敗・使用済みカードでは母集団を断言できない。断言しない従来文言に留める |
| 取得中の文言 | 「単語帳から選んでいます…」のまま | 取得中の事実を言っているだけで母集団の話ではない |
| アイコン・配置 | `dice`・2 行目のまま | 変えるのは文言だけ |
| 実装 | 純関数 `ChatRoomStore.randomWordButtonTitle(unpracticed: Int?) -> String` を追加し `TopicCardView` から使う | 文言の分岐をテスト可能にする（`wordBookTallyLabel` と同じ流儀）。カードは既に `wordBookTally` を受け取っているので新しい配線は不要 |

- コード中のコメントで機能名として「ランダムに選ぶ」と書いている箇所は据え置く
  （新文言にも「ランダムに選ぶ」が含まれ、検索も通る。リネームの churn を避ける）

## 対応方針

1. `ChatRoomStore` に純関数 `randomWordButtonTitle(unpracticed: Int?) -> String` を追加
   （nil → 「ランダムに選ぶ」 / 0 → 「全語からランダムに選ぶ」 / それ以外 → 「未練習からランダムに選ぶ」）
2. `TopicCardView.wordBody` のランダムボタンの `Label` 文言を
   `ChatRoomStore.randomWordButtonTitle(unpracticed: wordBookTally?.unpracticed)` に差し替え
3. 単体テスト: `WordBookTallyTests` に文言 3 分岐のテストを追加
4. `xcodebuild` でビルド + 既存テスト全パス
5. シミュレータで表示確認（ローカル backend + `-wordbook-base-url` + `-practice-mode word` で
   「未練習からランダムに選ぶ」が出ること。tally が取れない起動では従来文言のままであること）

## 影響範囲

- 変更: `ChatRoomStore.swift`（純関数 1 つ）/ `ChatRoomComponents.swift`（Label 文言）/
  `WordBookTallyTests.swift`（テスト追加）
- 触らない: ランダム出題の挙動（`randomWordChoice` / フォールバック / 診断ログ）・
  取得経路・カードのレイアウト

## テスト方針

- 単体テスト: 文言 3 分岐（nil / 0 / 正の数）
- シミュレータ: 集計ありのカードで新文言、集計なし（シークレット不一致）で従来文言を目視確認
- 実機確認はユーザーが実施
