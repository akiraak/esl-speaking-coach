# 次のトピック候補を「持ち越し + 1 件生成」にする

## 目的・背景

セッションが終わるたびにトピックカードの候補 3 件を毎回まるごと生成し直している。

- 選ばなかった 2 件は「話してもよかった」候補なのに、次のカードでは消えてしまう
- 毎回 3 件生成するぶん待ち時間（カードが「候補を考え中…」のまま）と料金が乗る

**やった 1 件だけを落として残りを持ち越し、生成は補充ぶんの 1 件だけ**にする。
全件の作り直しは「🔄 他の候補」を押したときだけにする。

## 対応方針

| 契機 | 今まで | これから |
| --- | --- | --- |
| 初回起動 | 3 件生成 | 3 件生成（持ち越し無し。変更なし） |
| セッション終了直後 | 3 件生成 | **持ち越し 2 件 + 生成 1 件** |
| 🔄 他の候補 | 3 件生成 | 3 件生成（変更なし） |

- **持ち越し**: セッションを始めたカードの候補から、選んだトピックを除いた残り（先頭から最大 2 件）。
  - 自作トピック・フリートークで始めた場合は候補が 1 件も消費されないので、
    表示順の先頭 2 件を持ち越す（常に「持ち越し 2 + 新規 1」の形を保ち、生成は必ず 1 件にする）
  - 起動直後（前のカードがない）・DEBUG の自動開始は持ち越し無し → 3 件生成
- **重複回避**: 持ち越したタイトルは新規 1 件の除外リストへ、
  持ち越したジャンルはサンプラーの除外ジャンルへ渡す（同じジャンルの候補が並ばないように）
- **表示**: 持ち越しがある間はカードを「候補を考え中…」で丸ごと隠さず、
  持ち越し 2 件のピルを出したまま「1 件追加中…」を添える。生成を待たずに選び始められる
- 持ち越しはメモリ上のみ（アプリを再起動したら持ち越し無し = 3 件生成）。
  タイムラインの過去カードはこれまでどおりグレーアウトして残す

## 影響範囲

- `EslSpeakingCoach/Claude/TopicSuggestionClient.swift`
  system prompt が「exactly three」固定なので、割り当ての件数ぶん生成する書き方に変える
- `EslSpeakingCoach/Conversation/ChatRoomStore.swift`
  持ち越しの保持（`startSession` で確定）、`postTopicCard` / `fillTopicCard` の件数・マージ
- `EslSpeakingCoach/Conversation/ChatRoomComponents.swift`
  `TopicCardView` の生成中表示（持ち越しがあるときはピルを出したまま）
- `docs/specs/conversation-design.md`（トピック生成の呼び出しタイミング・件数、付録 B）

## Phase

### Phase 1: 生成件数を可変にする

- `TopicSuggestionClient.systemPrompt` を「user メッセージの割り当て 1 件につき候補 1 件」に書き換える
- `TopicAssignmentSampler.sample(count:)` は既に件数を取れるのでそのまま使う

### Phase 2: 持ち越しの実装

- `ChatRoomStore` に持ち越し候補を保持し、`startSession` で「選んだ 1 件を除いた最大 2 件」を確定する
- `postTopicCard` は持ち越しを初期候補としてカードを出し、生成は 1 件だけ（持ち越し無しなら 3 件）
- 生成結果は持ち越しの後ろに足す。除外リスト（タイトル / ジャンル）に持ち越しを含める
- 生成が失敗しても持ち越しは残す（カードが空にならない）

### Phase 3: 表示と仕様反映

- `TopicCardView`: 持ち越しがあるときは候補を出したまま「1 件追加中…」
- `docs/specs/conversation-design.md` を実装に合わせて更新

### Phase 4: テストと確認

- ユニットテスト
  - 持ち越しの切り出し（選んだ 1 件が落ちる / 最大 2 件 / 自作トピックのときは先頭 2 件 / カード無しは空）
  - 生成結果とのマージ（順序・重複タイトルの排除・件数上限）
  - 割り当て 1 件のリクエストボディ（`makeRequestBody` に 1 件だけ渡したときの user メッセージ）
- シミュレータで「候補を選ぶ → 会話 → 終了」を通し、
  次のカードが「持ち越し 2 + 新規 1」になること、🔄 で 3 件とも入れ替わることを確認する

## 実施結果（2026-07-27）

- Phase 1〜4 すべて実施。ユニットテスト 9 件追加・全 165 件パス
- シミュレータ通し確認: 終了後のカードが「持ち越し 2 件 + 新規 1 件」になること、
  利用量記録で **初回カード 121 output tokens → 補充カード 55 output tokens** と
  生成が 1 件ぶんに落ちていることを確認（カードから選ぶ導線は DEBUG 起動引数
  `-start-from-card` で自動化した）
- 🔄 は実装上 `carryOver: []` で 3 件生成する経路のまま（タップ操作が要るためシミュレータ未確認）

## テスト方針

- 持ち越しとマージは `ChatRoomStore` の static な純粋関数として切り出してユニットテストする
  （ストアは `@MainActor` + ネットワークを持つのでロジックだけを外に出す）
- 生成件数はリクエストボディの検証で担保する（実 API は叩かない）
- 実機確認は不要（音声パスに触れないため）。シミュレータでの通し確認までとする
