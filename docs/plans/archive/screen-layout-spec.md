# 画面レイアウトと仕様を決める

## 目的・背景

音声レイヤの方式が確定した（ターン制+Claude + Gemini TTS、2026-07-25）ので、日常使用する製品画面のレイアウトと仕様を決める。現状の `ConversationView` は音声レイヤ検証用（エンジン切替・RMS 表示・レイテンシ表示）であり、そのまま使う UI ではない。

ユーザー要件（2026-07-25 ヒアリング）:

- LINE などの SNS チャット風の画面にする
- グループチャット形式で、AI 2 キャラと会話する
- ユーザーは音声入力とテキスト入力を切り替えできる
- トピックを事前にいくつか生成し、その中から選択して会話を開始できる

## 対応方針

1. 検討ポイントごとに複数案を出し、ユーザーが選択して方針を決定する（本ファイル）
2. 決定内容を画面仕様書 `docs/specs/screen-layout.md` にまとめる
3. 実装は別タスク（TODO「会話画面の UI」「会話履歴の永続化」「セッション後のフィードバック生成」）で行う

## 画面一覧（ベースライン・全案共通）

| 画面 | 役割 |
| --- | --- |
| トーク画面 | LINE 風グループチャット。会話の主画面 |
| トピック選択 | 事前生成したトピック候補から選んで会話開始（表示形態は検討ポイント②） |
| 履歴 / フィードバック | 過去セッションの記録とフィードバックの閲覧（配置は検討ポイント①に依存） |
| 設定 | API キー・キャラ・音声などの設定（既存 `SettingsView` を拡張） |

## 検討ポイントと案

### ① トップ画面・全体フロー

**案 A: 常設ルーム型（推奨）**

LINE のグループトークの実態に最も近い形。トーク一覧は作らず、起動すると常設のグループトークルームが即座に開く。セッション（1 トピックの会話）は「トピック開始カード 〜 フィードバックカード」の区切りとして同一タイムラインに積まれていく。

```
┌────────────────────────────┐
│  ESL Group (3)          ⚙  │ ← ルーム名 + メンバー数 + 設定
├────────────────────────────┤
│ ‹前回までの履歴を遡れる›     │
│ ── 7/25 Travel plans ──    │ ← セッション区切り
│ [Mia] Where would you go?  │
│          I'd go to Peru ▷  │
│ ┌────────────────────────┐ │
│ │ 📝 Session Feedback     │ │ ← フィードバックもカードで投稿
│ └────────────────────────┘ │
│ ┌────────────────────────┐ │
│ │ 📌 次のトピックを選ぶ 🔄 │ │
│ └────────────────────────┘ │
├────────────────────────────┤
│ ⌨  ● 〰〰〰〰〰〰〰  ⏸    │ ← 入力バー（検討ポイント③）
└────────────────────────────┘
```

- 長所: 起動 → 即会話でフリクション最小（発話量を稼ぐという第一目的に合致）。画面数が最少
- 短所: 過去セッションの一覧性が低い（補完として、設定メニュー配下に「フィードバック一覧」画面を置く）

**案 B: トーク一覧型**

LINE のトーク一覧を起点にし、1 セッション = 1 トークとして分ける。「+」→ トピック選択 → 新規トーク作成。

```
┌────────────────────────────┐
│ トーク                  ＋  │
├────────────────────────────┤
│ 👥 7/25 Travel plans       │
│    最後のメッセージ… 12:30  │
│ 👥 7/24 Weekend movies     │
│    Feedback あり     21:05 │
├────────────────────────────┤
└────────────────────────────┘
```

- 長所: セッション単位の履歴・フィードバックの一覧性が高い。SwiftData のモデル（Session 単位）と素直に対応
- 短所: 会話開始までのタップ数が増える。個人ツールとしてはやや大げさ

**案 C: タブ型**

「トーク」「履歴・成績」「設定」の 3 タブ。トークタブは案 A の常設ルーム。

- 長所: フィードバックの振り返り導線が常時見える
- 短所: タブに足るコンテンツが当面ない（履歴タブが薄い）

### ② トピック選択 UI

**案 A: チャット内カード（推奨）**

トピック候補（3 件程度 + フリートーク）を、トークルーム内に投稿されるカードとして表示する。タップで選択、🔄 でシャッフル（再生成）。セッション終了後に自動で次のカードが投稿される。

```
│ ┌────────────────────────┐ │
│ │ 📌 今日のトピック        │ │
│ │ ▷ Planning a trip       │ │
│ │ ▷ Food you can't quit   │ │
│ │ ▷ Free talk             │ │
│ │            [🔄 他の候補] │ │
│ └────────────────────────┘ │
```

- 長所: LINE の世界観がチャット内で完結し、追加画面が不要。実装もチャット item の一種として自然
- 短所: カードが履歴に残る（選択済みカードはグレーアウト表示にする）

**案 B: シート型ピッカー**

会話開始時にハーフモーダルのシートを出し、カードグリッドから選ぶ。カテゴリタグやレベル表示を添えられる。

- 長所: 候補を多く出せる。トピックのメタ情報（カテゴリ・難易度）を見せやすい
- 短所: チャット世界観から一瞬離れる。画面が 1 枚増える

**案 C: おまかせ即開始**

マイクをタップしたら即おまかせトピック（またはフリートーク）で開始。選びたいときだけ長押し等でピッカーを開く。

- 長所: フリクション最小
- 短所: 「選んで始める」という要件からは外れ、トピック生成の存在感が薄れる

### ③ 音声 / テキスト入力の切替 UI

**案 A: 入力バー変形（推奨）**

LINE と同じ入力バーを基本形にし、マイクボタンで音声モードへ「変形」する。音声モードはハンズフリー連続（サーバ VAD でターン検出、barge-in 可）。モードはセッションをまたいで保持。

```
テキストモード:
│ [🎤] [Aa メッセージを入力…] [↑] │
        ↓ 🎤 タップ
音声モード（ハンズフリー連続）:
│ [⌨] ● 〰〰〰〰〰〰〰〰 [⏸]   │
  聞き取り中は波形が動く / ⏸ で一時停止
  ⌨ タップでテキストモードへ戻る
```

- 長所: LINE の操作感に一致。ハンズフリー前提（発話量を稼ぐ）と両立
- 短所: モードが今どちらかの視認性に注意が必要（バーの色・波形で明示する）

**案 B: 常設トグル**

入力バーの上に 音声 / テキスト の segmented control を常設する。

- 長所: 状態が常に明示的
- 短所: LINE らしさが薄れ、縦方向のスペースを常時消費する

**案 C: 長押し PTT（push-to-talk）**

テキストバー常設、マイクボタン長押しの間だけ録音する。

- 長所: 誤認識が減る
- 短所: ハンズフリーでなくなり、発話量を稼ぐ目的・既存のサーバ VAD 実装と相性が悪い

### ④ AI 2 キャラのターン進行（チャット表示に影響する範囲）

**案 A: 台本方式・1 呼び出し（推奨）**

ユーザー発話ごとに Claude を 1 回呼び、両キャラ分の発話（0〜2 発話。どちらが・何回話すかはモデルが状況判断）を speaker タグ付きで受け取る。キャラごとに TTS voice を切り替えて順に読み上げ、吹き出しもキャラごとに順次表示する。

- 長所: レイテンシ・コストが最小。キャラ同士の掛け合い（相槌・ツッコミ）が自然に書ける
- 短所: 文単位 TTS ストリーミング（`SentenceChunker`）に speaker 属性を通す実装が必要
- 補足: 「メインキャラ + 相槌キャラ」のバランスはシステムプロンプト側で調整可能（案 C を包含する）

**案 B: キャラ別 2 呼び出し**

キャラごとに別 system prompt で Claude を呼ぶ。

- 長所: 人格の独立性が最も高い
- 短所: レイテンシ・コストが約 2 倍。発話順・重複の調停が難しい

**案 C: メイン + 相槌固定**

1 キャラが会話を主導し、もう 1 キャラは時々短い相槌・別視点だけを差し込む役割に固定する。

- 長所: 制御が単純
- 短所: 役割が固定的で掛け合いの幅が出ない（案 A のプロンプト調整で同じ効果を出せる）

## 共通仕様（全案共通・仕様書に反映する項目）

- **キャラ表示**: AI 2 キャラは名前・アバター・人格・TTS voice をアプリ内定義の固定値で持つ（設定画面での編集は将来）。AI の吹き出しは左寄せでアバター + 名前ラベル付き、ユーザーは右寄せ・アクセントカラーの吹き出し（LINE 準拠。自分のアバターは出さない）
- **進行状態表示**: 応答生成中は LINE 風の「〜が入力中…」インジケータ。読み上げ中は発話中キャラのアバター横にスピーカーアイコン。聞き取り中は入力バーの波形アニメーション（検証用の RMS 数値・レイテンシ表示は製品 UI から外し、DEBUG のみ残す）
- **ライブ文字起こし**: 発話中の partial transcript は右側に半透明の吹き出しで表示し、確定したら通常の吹き出しに置き換える（現行挙動を踏襲）
- **システムメッセージ**: エラー・再接続・セッション区切りは中央寄せのグレー小文字テキスト
- **会話終了の導線**: 「トピックを終える」操作（ツールバーまたはメニュー）でセッションを終了し、フィードバック生成をトリガーする。フィードバックの詳細仕様は別タスク
- **既読・スタンプ・画像等の LINE 機能は対象外**。ダークモード対応はする

## 決定事項（2026-07-25 ユーザー確認）

- **③ 入力切替**: 案 A（入力バー変形）。マイクボタンで音声モードへ切り替える
