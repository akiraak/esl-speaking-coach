# 単語・熟語の学習を継続する仕組み（練習した語を次回のカードに出す）

2026-07-28 起票 / 同日実装完了（確認記録は `docs/specs/word-practice.md`「前に練習した語のピル」）。
実装は計画どおりで、追加したのは E2E 用に `-start-from-card` を単語カードへ効かせた 1 点だけ。
関連仕様: [word-practice.md](../specs/word-practice.md) / [screen-layout.md](../specs/screen-layout.md)。

## 目的・背景

単語練習モードは「1 セッション 1 語をじっくり」練習できるが、**その語がその場で終わる**。
次に何を練習するかを毎回自分で思いつく必要があり、一度やった語は二度と出てこない。

そこで仕組みは 2 つだけにする。

1. **単語を保存する**
2. **次回学習するときに表示する**

これは `word-practice.md` の「やらないこと」に挙げていた
「単語カードに『前に練習した語』をピルで並べる復習導線（保存はしてあるので後から足せる）」そのもの。
SRS・定着判定・フィードバックからの自動取り込みは**入れない**（下記「今回やらないこと」）。

## 決定サマリ

| 項目 | 決定 |
| --- | --- |
| 保存する語 | **単語モードで練習した語**（セッション開始時に入力・選択した語） |
| 保存先 | **既存の `ChatSessionRecord.topicTitle`（mode=word）**。専用モデルは作らない |
| 表示場所 | 単語カード（📖 次に練習する単語）の「単語を入力」ボタンの上 |
| 並び順 | **新しい順**（直前に練習した語が先頭） |
| 重複 | 正規化して除去し、**最新の表記を 1 件だけ**残す |
| 件数 | 最大 6 件 |
| タップ | その語で**即セッション開始**（入力アラートを挟まない） |
| 削除 | 専用 UI は作らない（管理画面のセッション削除で消える） |

**新しい永続化モデルを増やさない**のが今回の要点。マイグレーションもストアの新設も無く、
すでに保存されているデータの見せ方を足すだけで「保存する / 次回出す」が成立する。

## 仕様

### 保存

単語モードでセッションを始めた時点で `ChatSessionRecord(topicTitle: 練習語, mode: .word)` が
保存される（**実装済み**）。今回の変更は不要。

- 入力した語も、カードのピルから選んだ語（= 再練習）も同じ経路で保存される
- 同じ語を何度練習しても履歴には都度 1 セッションずつ残る（表示側で重複を畳む）

### 表示

単語カードのレイアウト（未使用時）:

```
┌──────────────────────────┐
│ 📖 次に練習する単語         │
│ [get around to] [look up] │ ← 前に練習した語（新しい順・最大 6 件・折り返し）
│ [take after]   [put off]  │
│ [＋ 単語を入力]            │
└──────────────────────────┘
```

- ピルは既存のトピック候補ピルと同じ見た目（`ChatTheme.topicPill*`）。折り返しは
  `LazyVGrid(columns: [GridItem(.adaptive(minimum: 100))])` で済ませる
- **練習履歴が無いときはピルを出さない** = 現状（入力ボタンだけ）と同じ見た目になる
- 使用済みカード（過去のカード）の見た目は変えない。今までどおり練習した語だけを残し、
  グレーアウト + タップ無効（既存の `isUsed` の扱いに乗る）
- 会話モードのカードには一切影響しない

### 選択の重複除去（純関数）

`ChatRoomStore.practicedWordSuggestions(from:limit:)` として切り出しユニットテストする。

- 入力は新しい順の練習語リスト、出力は表示するピルのリスト
- 正規化キー = 小文字化 + 前後空白除去 + 連続空白の畳み込み。同じキーなら**新しい方の表記**を残す
- 空文字・空白のみは落とす
- 上限 `limit`（6）で切る

### 再練習セッション

**特別扱いを一切しない**。ピルから始めても入力から始めても同じ `[New word: X]` で、区切りも
`7/28 単語: X`、system prompt もフィードバックも同じ。単語練習の進行（意味 → 例文 → 使う →
別文脈）は 2 回目でもそのまま成立する。

## 実装

| ファイル | 変更 |
| --- | --- |
| `Persistence/ChatHistoryStore.swift` | `recentWords(limit:)` を**新しい順**で返すように直す（現状は古い順の `suffix`・重複そのまま。未使用のメソッドなので呼び出し側への影響なし） |
| `Conversation/ChatRoomStore.swift` | `TopicCard` に `wordSuggestions: [String]` を追加。`postTopicCard()` の単語モード分岐で履歴から詰める。純関数 `practicedWordSuggestions(from:limit:)` を追加 |
| `Conversation/ChatRoomComponents.swift` | `TopicCardView.wordBody` に未使用時のピル表示を追加 |
| `Conversation/ChatRoomView.swift` | ピルのタップを `store.startSession(topic:fromCard:)` へ繋ぐ |

- モデル・マイグレーション・新規ストア・API 呼び出しは**なし**
- `postTopicCard()` は同期的に履歴を読むだけなので、生成待ちの状態（`isLoading`）は増えない

## テスト方針

- 単体: `practicedWordSuggestions` の重複除去・順序（新しい順）・件数上限・空白の扱い。
  `ChatHistoryStore.recentWords` が新しい順で返ること（mode=word 以外が混ざらないこと）
- シミュレータ E2E: 既存の起動引数を使い、
  `-practice-mode word -start-word "get around to" -send-text ... -end-session` で
  終了後に投稿される次のカードへ `get around to` のピルが出ることを確認。
  さらにそのピルから開始した 2 回目のセッションが同じ語で始まることを確認する
- 実機: ピルの折り返し・タップ範囲・長い熟語（4〜5 語）の表示崩れを確認する

## 今回やらないこと

検討はしたが、「保存する / 次回出す」に絞るため今回のスコープから外す。必要になったら別タスクで。

| 見送るもの | 理由 |
| --- | --- |
| SRS（復習期日・箱） | 出す語を 6 件に絞れば、期日計算が無くても目に入る。仕組みが増えるわりに効果が読めない |
| 定着判定（会話で使えたかの検出） | フィードバックのプロンプト改訂（キャッシュ作り直し）を伴う。まず出す導線だけで様子を見る |
| フィードバックの `try_phrases` を単語帳へ自動取り込み | 語の供給は増えるが、練習していない語がカードに並ぶと「前にやった語」の意味が薄れる |
| 会話モードへの対象語注入（`[Target phrases: ...]`） | `CoachSystemPrompt` の改訂が必要で、会話品質への影響が読めない |
| 単語帳の専用画面・削除 UI | 専用モデルを作らない方針とセット。消したい語は管理画面のセッション削除で消える |
| 進捗表示（今週 N 語・ストリーク） | 個人ツールに管理指標は要らない |
