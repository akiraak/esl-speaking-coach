## 目的・背景

単語モードのカードに「ランダムに選ぶ」（未練習の語からランダム出題）を追加したが、
単語帳に何語あり、そのうち何語が未練習なのかがアプリ上のどこにも見えない。
残りがどれだけあるか分かると単語帳の消化のモチベーションになり、
「ランダムに選ぶ」が何語の母集団から選んでいるのかの説明にもなる。

単語カードに **単語帳の総数と未練習の数、練習済みの進捗（練習済み/総数とパーセント）** を表示する
（例: `練習済み 42/185語 22%・未練習 143語`）。

## 決定サマリ

| 項目 | 決定 | 理由 |
| --- | --- | --- |
| 「未練習」の定義 | **ランダム出題と完全に同一**: `practicedWordsAll()`（mode=word 全セッション）と `normalizedWordKey` で照合した除外の残り（`ChatRoomStore.unpracticedWords`） | 表示する数字と「ランダムに選ぶ」の母集団が一致していないと嘘の表示になる。定義を二重に持たない |
| データ取得 | 既存の `WordBookClient.fetchAllWords(secret:)` を流用（全件取得 → クライアント側で集計） | 総数だけなら `limit=1` の `total` で取れるが、未練習数には全件が必要。経路を増やさない。個人単語帳（約 185 語）なので 1 リクエスト |
| 表示対象 | **未使用の単語カードのみ**。使用済み（履歴）カードには出さない | 過去カードに古い数字を凍結表示すると誤解のもと。履歴カードの役割は「何を練習したか」だけ |
| 取得タイミング | 未使用の単語カードが現れるたび（`.task(id:)`）。= 起動時・モード切替・セッション終了で新カードが出るたびに取り直す | セッションが終わると練習済みが増えるので、新カードごとの再取得が自然なリフレッシュ境界 |
| ランダム出題との共用 | 「ランダムに選ぶ」実行時の取得結果（全件 + 未練習）でも表示を更新する | 同じデータを 2 度取らない。診断ログに出している `全N語 未練習M語` と画面が揃う |
| 取得中・失敗時 | **何も出さない**（スピナー・アラートなし。診断ログに 1 行だけ残す） | 受動的な情報表示であり主導線を邪魔しない。シークレット未設定・オフラインでもカードの他機能は今までどおり使える（案内はランダム/ピッカー実行時に出る） |
| 表示位置・文言 | カード見出し「📖 次に練習する単語」の下に caption で `練習済み 42/185語 22%・未練習 143語` | 総数・未練習数に加えて進捗（`5/100 5%` 形式）を出す。実装時に見た目で微調整。隣接 TODO「ランダムボタンの文言変更」とは別タスクとして扱う（下記・未決事項） |
| パーセントの丸め | **切り捨て**（`practiced * 100 / total` の整数除算）。総数 0 のときは行ごと非表示 | 四捨五入だと未練習が残っているのに 100% に見える瞬間ができる。切り捨てなら 100% = 全語練習済みが常に成り立つ。0 除算も自然に回避 |

- 全語練習済みのときは `未練習0語` とそのまま表示する（ランダム出題は全語フォールバックするが、
  それはボタン側の挙動。数字は事実を出す）
- アプリで練習したが単語帳に無い語（手入力の語）は集計に影響しない（`unpracticedWords` の仕様どおり、
  母集団は常に単語帳側）

## 対応方針

### Phase 1: 集計と状態管理（UI なし）

- `ChatRoomStore` に純関数 `wordBookTally(all:practiced:) -> (total: Int, unpracticed: Int)` を追加
  （中身は `all.count` と `unpracticedWords(all:practiced:).count`。表示とランダム出題で定義を共有する要。
  練習済み数・パーセントは `total - unpracticed` から導出するので tally には持たせない）
- 表示文言も純関数にする: `wordBookTallyLabel(total:unpracticed:) -> String?`
  （`練習済み 42/185語 22%・未練習 143語` を組み立てる。パーセントは整数除算の切り捨て。
  `total == 0` は nil を返して行ごと非表示）
- `ChatRoomView` に `@State private var wordBookTally: (total: Int, unpracticed: Int)?` と取得 Task を追加
  - 未使用の単語カードの出現をキーに `.task(id:)` で取得（カード ID + モードで発火）
  - シークレットは `KeychainStore.wordBookAPISecretAccount`（ランダム出題と同じ読み方）。
    未設定・取得失敗は `wordBookTally = nil` のまま + 診断ログ 1 行（アラートは出さない）
  - `startRandomWordSession` の成功経路でも取得済みデータから `wordBookTally` を更新する

### Phase 2: カード UI に表示

- `TopicCardView` にオプショナルの表示用パラメータ（例: `var wordBookTally: (total: Int, unpracticed: Int)? = nil`）を追加
- `wordBody` の見出し直下に caption で `wordBookTallyLabel` の文字列
  （`練習済み 42/185語 22%・未練習 143語`）を表示
  （nil のとき・使用済みカードのときは行ごと出さない。レイアウトが詰まるだけで崩れない）
- 未使用カードにだけ値を渡す（`ChatRoomView` 側で `card.isUsed` を見て nil を渡す）

### Phase 3: 検証

- 単体テスト: `wordBookTally` の集計（除外あり / 全語練習済みで 0 / 単語帳に無い練習語は無影響。
  既存 `RandomWordChoiceTests` の流儀・フィクスチャに合わせる）
- 単体テスト: `wordBookTallyLabel` の文言（`5/100` で `5%` / 切り捨て（199/200 → 99%）/
  全語練習済みで 100% / total 0 で nil）
- `xcodebuild` でビルド + 既存テスト全パス
- シミュレータ E2E: ローカル backend（esl-learning-assistant の run-server.sh）+ `-wordbook-base-url` +
  `-practice-mode word` で、
  (1) カードに総数・未練習数が出る
  (2) 1 語練習してセッションを終えると、新カードで未練習数が 1 減る
  (3) シークレット未設定 / backend 停止時は数字が出ないだけでカードの他機能は使える
- 実機確認はユーザーが実施（本番 esl.chobi.me に対する表示）

## 影響範囲

- 変更: `ChatRoomStore.swift`（純関数追加）/ `ChatRoomView.swift`（取得 Task と状態）/
  `ChatRoomComponents.swift`（カード表示）+ テスト
